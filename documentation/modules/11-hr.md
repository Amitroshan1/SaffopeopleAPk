# Module: HR

**Primary files:** `src/pages/HR/Hr.jsx` and sibling pages (locations, news, assets, archive, exit, ATS, etc.)

**API base:** `/api/HumanResource` (also `/api/accounts` for payroll-adjacent HR views)

## Routes (selection)

| Route | Purpose |
|-------|---------|
| `/hr`, `/updates` | HR console (same `Hr` component) |
| `/archive-employees` | Archive list / details |
| `/exit-employees` | Exit processing |

Many HR tools are **tabs/panels inside `Hr.jsx`** rather than separate routes (signup, punch edit, inbox, master options, password reset).

## Representative APIs

| Action | Path |
|--------|------|
| Dashboard | `GET /api/HumanResource/dashboard` |
| Inbox | `GET /api/HumanResource/inbox` |
| Master options | `GET /api/HumanResource/master/options` |
| Employee profile | `GET /api/HumanResource/employee/profile/:id` |
| Signup | `POST /api/HumanResource/signup` |
| Punch view / sessions | `/api/HumanResource/employee/punch/:id...` |
| Locations | `/api/HumanResource/locations` |
| Dept / circle master | `/api/HumanResource/master/department`, `.../circle` |
| News feed | `/api/HumanResource/news-feed` |
| Assign asset | `/api/HumanResource/assign-asset` |
| Holidays (user calendar) | `/api/HumanResource/holidays/user?year=&auto_seed=1` |
| Password reset send | `/api/HumanResource/send-password-reset` |
| Accounts profile bridge | `/api/accounts/employee-accounts-profile` |

## Guidance for new engineers

`Hr.jsx` is large. Prefer extracting new HR features into sibling files (pattern: `AddLocation.jsx`, `AddNewsFeed.jsx`) and importing them into the hub rather than growing the monolith further.
